# Данные и допущения

Источник — `src/generate_data.py`, генератор NumPy с seed=42. Период наблюдения:
01.06–30.09.2026 включительно, UTC. Регистрации: 01.06–31.08.2026.
Все идентификаторы и транзакции вымышлены. Даты представлены ISO-строками для SQLite.

## users — пользователи (3 000 строк)

| Поле | Значение |
|---|---|
| `user_id` | Уникальный идентификатор зарегистрированного пользователя |
| `signup_date` | Дата регистрации `YYYY-MM-DD` |
| `platform` | Фиксированная платформа: web / android / ios |
| `acquisition_channel` | Первый источник: organic / direct / paid_search / paid_social |

Organic — органический трафик; direct — прямые заходы; paid search — платный поиск;
paid social — платные соцсети. Стоимость привлечения не моделируется.

## events — события (54 320 строк)

| Поле | Значение |
|---|---|
| `event_id` | Уникальный идентификатор события |
| `user_id` | Ссылка на пользователя |
| `session_id` | Глобальный идентификатор сессии; одна сессия принадлежит одному пользователю |
| `event_time` | Время события `YYYY-MM-DD HH:MM:SS`, UTC |
| `event_name` | Название события |
| `platform` | Платформа на момент события |
| `app_version` | Версия: web / 2.0 / 2.1; постоянна внутри сессии |

| Событие | Смысл |
|---|---|
| `view` | Просмотр товара, вход в воронку |
| `add_to_cart` | Добавление в корзину |
| `checkout` | Начало оформления заказа |
| `purchase` | Успешно оплаченная покупка |
| `payment_error` | Ошибка оплаты после checkout |

В генераторе этапы происходят с интервалом 60 секунд. Сессия не пересекает полночь,
по одному событию каждого типа на сессию. После checkout возникает либо purchase,
либо payment_error. В реальном продукте отказ без события ошибки и повторная попытка
также возможны; здесь они не моделируются. SQL проверяет временной порядок этапов.

## orders — заказы (6 108 строк)

| Поле | Значение |
|---|---|
| `order_id` | Уникальный идентификатор заказа |
| `user_id` | Покупатель |
| `session_id` | Уникальная ссылка на сессию с purchase |
| `order_time` | Время оплаты, совпадает с purchase |
| `amount_kzt` | Сумма заказа в целых тенге, строго положительная |
| `status` | Только `paid` — оплачен |

## Модель поведения

Платформа распределена примерно как web 40%, Android 35%, iOS 25%.
Первый визит происходит в день регистрации, далее вероятность визита убывает
с возрастом пользователя и отличается по случайному индивидуальному коэффициенту.
Вероятность добавления в корзину задана по каналу; переход в checkout — 72%.
Оплата после checkout — 76%, а для Android 2.1 — 40%.
С 1 сентября Android-сессия с вероятностью 75% получает версию 2.1.
Суммы заказов — логнормальное распределение с ограничением 2 000–120 000 ₸.

Это допущения симуляции, а не установленные закономерности e-commerce.
Фактические доли отличаются от вероятностей из-за случайной выборки.
События отсортированы при генерации по пользователю; нельзя полагаться на порядок строк CSV.
Для любой последовательности нужно использовать `event_time` и явный `ORDER BY`.
